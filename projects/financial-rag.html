Financial RAG

An independent RAG project over Alicorp's Spanish quarterly reports: preserve table context, find the right reporting period, and measure what gets retrieved.

Personal project in progress. Python, BM25, multilingual E5, PyMuPDF and Claude API.

ProblemMethodResultsExamplesLimitations

Problem and scope

Financial reports repeat their vocabulary and structure. Finding a sales page is not enough if it belongs to the wrong quarter. And when PDF extraction separates every cell, a figure loses its relationship to the row it belongs to.

I built a pipeline combining PDF extraction, hybrid retrieval and citation-enabled generation. The work shown here measures reference-page retrieval; it does not yet establish the quality of generated answers.

The corpus contains four Alicorp reports, from 4Q23 to 3Q24, totalling about 100 pages. Of the 36 hand-annotated questions, 32 are answerable and four are not. The system retrieves a reference page among the first six chunks for 29 of the 32 answerable questions.

The set contains 22 figure lookups, 7 explanations, 3 cross-period comparisons and 4 questions the documents cannot answer. The annotations and evaluation decisions come from a single author.

Method

  1. Reconstruct table rows

    PyMuPDF provides word coordinates. The parser rebuilds visual lines and turns wide horizontal gaps into cell separators. The aim is to keep the label, period and figure together.

  2. Combine two kinds of search

    BM25 retrieves exact terms and figures; multilingual-e5-small embeddings help with paraphrases. Reciprocal rank fusion (RRF) combines both result rankings.

  3. Identify the question's period

    A rule-based detector recognises phrases such as “3T24”, “tercer trimestre de 2024”, or date ranges. Search is restricted to matching reports. Generalisation beyond these phrasings remains a limitation.

  4. Generate with documents and citations

    Chunks are passed to Claude as separate document blocks with citations enabled. References map back to a report and a page. The prompt requests abstention when an answer is missing, but that behaviour has not yet been evaluated end to end.

With layout-aware extraction, the period-filtered hybrid moves from BM25's 25/32 hits to 29/32: four additional questions. Compared with the unfiltered hybrid, the hit@6 gain is one question. The reranker improves first-position retrieval but lowers hit@3 and comparison coverage; it remains off by default.

Comparison with plain-text extraction

Plain-text extraction with hybrid search and a period filter reaches hit@6 = 0.938 (30/32), versus 0.906 (29/32) with layout-aware extraction. It also reaches hit@3 = 0.781 and comparison coverage = 0.639. Keeping rows together is useful context for the generator, but these data do not demonstrate an overall retrieval or answer-quality improvement. A one-question difference is not a robust conclusion.

Limitations and next steps

  • One company and four quarters do not represent financial documents in general. The corpus needs more companies and report formats.
  • The evaluation set is small and single-author. A larger set and a second annotator would support more reliable comparisons.
  • Period detection uses rules covering the evaluation-set phrasings. Generalisation to arbitrary questions has not been established.
  • The four unanswerable questions are excluded from these retrieval metrics. The model's ability to abstain still needs to be measured.
  • Answer evaluation is implemented, but results are not yet available: numeric accuracy, citation precision, whether the cited passage contains the expected figure, and abstention. The planned baseline uses the same model without documents.

Project availability. The source code is not public yet. This page shares the methodology, recorded results and question set so the work can already be inspected.
